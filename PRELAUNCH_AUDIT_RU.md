# Контрольная проверка перед первым GPU-тестом

Проверено 10 октября 2026. Платная GPU не запускалась.

## Подтверждено

- В Vast остался один Bernini RV2V Serverless Fixed v6.
- Образ vastai/comfy:v0.20.1-cuda-12.9-py312, ветка fix/supervisor-startup-status,
  SDK_VERSION=1.8.3, bucket bernini-rv2v.
- Benchmark ID e400be40f9984f619b2b892ab7351e9d сохранён в шаблоне.
- Endpoint ylxfcvlr (40317) остановлен, workgroup отсутствует, workers 0,
  Minimum Workers=0, Max Workers=1, Minimum Load=0. Баланс при проверке $3.82.
- Ключи R2 не извлекались для сетевого теста. Существование новых объектов
  benchmark и права чтения/записи из GPU ещё требуют проверки при запуске.

## Найдено и исправлено в этой проверке

1. В upstream ComfyUI v0.20.1 нет context_latents, необходимых BerniniStudio.
   Теперь установщик переводит ядро на официальный merge commit
   f8e51b674c75f41b3960d65ce83f77301ab297c9 (версия в исходниках 0.24.0),
   устанавливает его requirements и проверяет CONDList/context_latents.
   При изменённых tracked файлах ядра установка останавливается без перезаписи.
   Установленные torch/torchvision/torchaudio закрепляются constraints:
   автоматической замены CUDA-сборки на другую не будет.
2. BerniniStudio закреплён на ca69274a2d2135052489bc0c67a2d79a64225e86,
   VideoHelperSuite на 4d907bee61e92c2e65af3bd6383a4e4d356126d1.
   Произвольный свежий main больше не используется.
3. SDK по умолчанию выполняет warmup плюс benchmark. Warmup отключён:
   первый тест выполняется один раз и включает загрузку модели. Оценка скорости
   консервативная, а не ускоренная кешем повторного идентичного ComfyUI prompt.
4. Preflight проверяет все 14 типов узлов данного workflow.
5. Ошибки генерации записываются в приватный лог bridge, HTTP-ответ остаётся общим.
6. В архив включено исправление импорта для изолированного ComfyUI Portable Python.

## Порядок холодного запуска

Docker образ -> entrypoint.sh -> официальный Vast bootstrap -> наш worker.py
-> зависимости PyWorker -> проверка трёх объектов benchmark в R2 -> закреплённые
узлы и ядро ComfyUI -> зависимости ядра/узлов -> проверка поддержки Bernini
-> проверка всех HF источников -> загрузка и SHA256 -> перезапуск ComfyUI
-> preflight (модели, пути, место, ffmpeg/ffprobe, 14 узлов)
-> private bridge 127.0.0.1:18300 -> Vast SDK -> benchmark -> готовность worker.

## Что скачивается

Шесть файлов, всего 38 166 043 831 байт (38.17 GB / около 35.55 GiB):
- Bernini HIGH mxfp8: 14 966 031 368 байт.
- Bernini LOW mxfp8: 14 966 031 368 байт.
- HIGH LoRA: 630 697 104 байт.
- LOW LoRA: 613 561 776 байт.
- Wan VAE: 253 815 318 байт.
- UMT5 text encoder: 6 735 906 897 байт.

Дополнительно нужны Docker-образ, git-репозитории и Python-пакеты.
Модели скачиваются в HF cache на файловой системе models и подключаются hardlink,
без второй полной копии. Точные pinned источники, размеры и SHA256 в manifest.
Ollama/LLM для промпта не нужны: auto_enhance=false.

## Проверки и ограничения

53 теста и 18 subtests прошли. В новом тесте реальные FFmpeg/ffprobe разбили
96 кадров на фрагменты 81/17, собрали обратно ровно 96 кадров и сохранили звук;
только ComfyUI inference заменён имитацией. Это не проверка GPU-генерации.
Shell syntax, Python syntax и diff checks проходят. Исходники закреплённого
ядра содержат нужную поддержку. Ранее все шесть HF источников проверены по
metadata через фактический код установщика; полные веса локально не скачивались.

Не проверены без GPU: фактический состав Docker-образа, установка requirements
в его окружении, драйвер выбранного хоста, CUDA kernels, VRAM, inference,
Vast benchmark/маршрутизация, качество лица/волос и стыков фрагментов.
Не обещается полная идентичность или отсутствие артефактов.

## Действия пользователя

1. Сохранить текущие r2_config.env, vast_config.env, benchmark_job_id.txt.
2. Проверить наличие benchmark_configured.txt: одна строка
   e400be40f9984f619b2b892ab7351e9d. benchmark_job_id.txt содержит тот же ID.
3. В R2 сохранить jobs/e400be40f9984f619b2b892ab7351e9d/ с source.mp4,
   reference.jpg, workflow_api.json. Не удалять benchmark после теста.
4. В vast_config.env endpoint должен быть ylxfcvlr; API key хранить локально.
5. Если app.py исправлен вручную и UI уже создал benchmark, повторная
   переустановка локального интерфейса не нужна. В новом архиве исправление есть.
6. Пополнить баланс и согласовать максимальные расходы теста. Баланс не равен
   технически установленному лимиту расходов; автоматический лимит не настроен.
7. Первый запуск: один worker, одна GPU от 80 GB VRAM, диск 120 GB,
   CUDA capability хоста не ниже 12.9. Использовать единственный Fixed v6 шаблон.
8. Сначала добиться успешного benchmark. Затем короткое видео 3-5 секунд через UI.
   После первого результата проверить лицо, волосы, движения, длительность и звук.
   Более длинное видео проверять отдельно, после оценки затрат и стыков.

Ручной установки моделей или изменения PYWORKER_REF не требуется.
Старый benchmark не надо пересоздавать ради исправлений серверного кода.
