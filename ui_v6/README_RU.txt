BERNINI RV2V — интеграция твоего оригинального Windows-интерфейса (прототип)

СОХРАНЕНО: твой дизайн, portable Python, автоматическое определение длительности MP4 вместо ручного выбора кадров,
создание ZIP задания и загрузка в Cloudflare R2.
ДОБАВЛЕНО: одна кнопка «Загрузить и запустить генерацию», отображение
статуса/процентов текущего сэмплирования, скачивание MP4 и ручное удаление
всех объектов конкретного задания из R2.
PNG/JPG теперь приводится к reference.jpg, который ожидает GPU-мост.

1. Распакуй архив в НОВУЮ папку. Не перезаписывай рабочую копию.
2. Запусти INSTALL_R2_WINDOWS.bat (boto3, requests, Pillow).
3. Скопируй r2_config.example.env -> r2_config.env и внеси 4 ключа R2.
4. Скопируй vast_config.example.env -> vast_config.env. Внеси действительный
   HTTPS адрес Serverless обработчика /generate/sync и VAST_API_KEY.
   ВАЖНО: Serverless endpoint ЕЩЁ НЕ СОЗДАН/НЕ ПРОВЕРЕН, поэтому сейчас
   полноценно отправить видео на GPU через эту кнопку нельзя.
5. Запусти START_WINDOWS.bat, открой http://127.0.0.1:8765/.
6. Выбери видео, фото и число кадров, нажми одну кнопку. При корректной
   настройке endpoint интерфейс подготовит workflow, загрузит в R2,
   отправит job_id в Vast и начнёт опрос R2 status.json каждые 3 секунды.
7. После успешной генерации появится кнопка «Скачать готовое MP4».
   «Удалить файлы из облака» удаляет исходники, workflow, статус и результат
   ТОЛЬКО для этого задания, и только после успеха/ошибки.

АВТОМАТИЧЕСКАЯ ОЧИСТКА R2 — СДЕЛАТЬ ОДИН РАЗ В CLOUDFLARE:
Cloudflare Dashboard -> R2 -> bernini-rv2v -> Settings -> Object lifecycle
rules -> Add rule -> prefix jobs/ -> Expire objects after 7 days.
Не ставь правило на весь бакет: другие данные могут быть важны.
Правило не установлено автоматически; сначала убедись, что 7 дней достаточно.
Cloudflare удаляет объекты не мгновенно (обычно в течение 24 ч после срока).
Для всех jobs/ это касается также результатов, которые ещё не скачаны.

СЕКРЕТЫ: не присылай и не публикуй r2_config.env или vast_config.env.
R2 должен оставаться приватным. UI доступен только на 127.0.0.1.
Не создавай платный Vast endpoint до проверки bootstrap/SDK/маршрута.

ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ:
- Новый интерфейс не проверен на живом Vast Serverless; это интеграционный код.
- При закрытии UI его текущие задания перестают отображаться (R2 не удаляется).
- Процент сэмплирования не является общим процентом генерации.
- Если процесс Python перезапустить, скачивание по старому job_id через UI
  пока не поддерживается. Lifecycle по-прежнему удалит файлы по сроку.
- Старые локальные папки jobs/ и ZIP автоматически не удаляются.
- Внешний URL worker зависит от реальной конфигурации Vast Serverless.

ПОЛНАЯ ДЛИТЕЛЬНОСТЬ (НОВОЕ В V4):
- Нужен ffprobe.exe (из FFmpeg) в PATH Windows или переменная BERNINI_FFPROBE.
- Перед отправкой приложение определяет длительность MP4 и считает примерное
  число кадров при 16 FPS. Выбор 17/33/49/81/161 кадров убран.
- GPU должен использовать обновлённый r2_bridge.py с BERNINI_FULL_VIDEO=1
  (по умолчанию), long_video_runner.py и video_chunks.py.
- Работник нормализует видео до 16 FPS, считает реальные кадры, обрабатывает
  последовательные части максимум по 81 кадру, склеивает, возвращает аудио
  исходника и проверяет, что выход содержит все кадры.
- 16 FPS — частота из твоего рабочего workflow. Она может отличаться от
  исходного FPS. Длительность сохраняется с погрешностью до ~1/16 секунды.
- На границах частей возможны визуальные скачки личности/движения: требуется
  платный GPU-тест на ролике >5 секунд. Склейка не гарантирует идеальной
  временной согласованности.
- Защитный предел: 10 минут; длинные видео могут требовать многих GPU-
  генераций, занимать часы и стоить дорого.
- Старый GPU уже удалён, поэтому длинные ролики на H100 ещё не проверены.


V5: В vast_config.env используй BERNINI_ENDPOINT_NAME и VAST_API_KEY.
Запросы идут через официальный Vast Serverless SDK (endpoint.request), а не прямой URL GPU.
Запусти INSTALL_R2_WINDOWS.bat для установки SDK.
Без созданного и проверенного Vast endpoint генерация не запустится.

АВТОМАТИЧЕСКИЙ BENCHMARK (v6)
При первой загрузке через интерфейс программа создаёт отдельный 17-кадровый
benchmark из выбранного MP4, загружает его в R2 и сохраняет ID локально в
benchmark_job_id.txt. Не нужно выбирать видео/фото второй раз.

ВАЖНО: Vast.ai требует этот ID в переменной BERNINI_BENCHMARK_JOB_ID
на стороне endpoint. Интерфейс НЕ изменяет секреты Vast автоматически.
После добавления переменной в Vast создай benchmark_configured.txt рядом
с app.py, впиши туда только ID из интерфейса. После этого кнопка отправляет
задания на Vast. Первоначальный benchmark требует GPU при запуске Vast.
Не запускай платный GPU до проверки готовности моделей и worker.
Для FFmpeg запускай INSTALL_R2_WINDOWS.bat: ставится imageio-ffmpeg.
Конфигурационные файлы с ключами никогда не отправляй в чат.
